# Letter-to-Word Correction using LSTM

This repository contains an AI-based letter-to-word reconstruction system designed as a supporting module for a sensor-based sign language recognition glove.

The system takes noisy sequences of predicted letters (as produced by a glove-based classifier) and reconstructs the intended word using a sequence learning model, followed by confidence-based output control.

---

## Project Motivation

In sensor-based sign language systems, letter-level predictions are often affected by sensor noise, finger misalignment, and partial or unstable gestures. A single incorrect letter can result in an incorrect word.

This project addresses that problem by introducing an AI correction layer between letter recognition and speech output.

---

## System Overview

Noisy Letter Sequence  
→ Letter-to-Word LSTM Model  
→ Confidence-Based Filtering  
→ Corrected Word Output  

This module is designed to integrate seamlessly with a sign language recognition glove and a text-to-speech (TTS) system.

---

## Features

- Synthetic dataset generation with realistic letter-level noise  
- LSTM-based sequence model for letter-to-word reconstruction  
- Confidence gating to prevent unreliable outputs  
- Live interactive inference script  
- Modular design suitable for real-time deployment

## Model Details

Architecture: Embedding → LSTM → Fully Connected layer  
Input: Fixed-length letter sequences with padding  
Output: Word-level classification over a predefined vocabulary  
Loss Function: Cross-entropy loss  
Optimizer: Adam  

A confidence threshold is applied at inference time to avoid incorrect spoken outputs.

---

## Running the Live Demo

Requirements:
- Python 3.9 or later  
- PyTorch  
- pandas  

Run:
python live_test.py  

Example:
Input letters: HELLP  
Prediction: HELLO (confidence: 0.81)

## Notes on Model Weights

Trained model weights (.pt) and vocabulary mappings are intentionally excluded from version control to keep the repository lightweight, encourage reproducibility, and avoid large binary files in GitHub history.

They can be generated by running Training.ipynb or shared separately if required.
